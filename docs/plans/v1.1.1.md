## 1. 目标 / 非目标

**目标**：任何 EPUB（包括自带 `@page { margin: 0 }` 的 InDesign / HTML 导出书）转换后，正文页必须使用本项目 A4 页边距（18mm 上 / 16mm 左右 / 20mm 下），与《毛泽东选集》《Spec-Driven AI Engineering》等现有输出一致。

**非目标**：不改版式设计；不改正文/标题字号策略（字号问题见 §8，另行决策）；不引入新依赖；不重构渲染链路。

## 2. 事实与证据（2026-10-20 实测）

### 2.1 现象
- `Systematic Trading` PDF：204 页，正文第 7 页起，文本 bbox 例如第 13 页 `x0=0.0, y0=1.3, x1=595.5, y1=818.1`（页面 595×842）；197 个正文页中 **193 页左边距 < 10pt、132 页上边距 < 10pt**。
- 对照：《毛泽东选集》正文 `x0=51–74pt`；`Spec-Driven` 正文 `x0=51pt, x1=543.8pt`；生成的目录页也有正常边距。

### 2.2 EPUB 侧
- 该 EPUB 的 `OEBPS/css/idGeneratedStyles.css` 含：`@page { margin : 0px 0px 0px 0px; }`（InDesign 导出，供自带边距的阅读器使用；本身不是损坏文件）。

### 2.3 代码侧
- [normalizer.py:61](../../src/epub2pdf/core/normalizer.py#L61) `PRINT_CSS`：`@page { size: A4; margin: 18mm 16mm 20mm 16mm; }`；[:62](../../src/epub2pdf/core/normalizer.py#L62) `@page :first { margin-top: 0; }`。
- `_html5_wrap`（[:542](../../src/epub2pdf/core/normalizer.py#L542)）输出顺序：`PRINT_CSS`（:550）→ 内联 EPUB CSS（:551）→ `POST_EPUB_CSS`（:552）；`_concat_css`（[:564](../../src/epub2pdf/core/normalizer.py#L564)）只清 `@charset`，不清 `@page`；`normalize()` 在 [:785](../../src/epub2pdf/core/normalizer.py#L785) 生成 `inline_css`。
- 同优先级 `@page` 后出现者生效 ⇒ EPUB 的 `margin:0` 覆盖我们的 A4 页边距；`POST_EPUB_CSS` 未重新声明 `@page`，无兜底。
- [renderer.py:250-259](../../src/epub2pdf/core/renderer.py#L250-L259) CDP 传 `marginTop/Bottom/Left/Right = 0`；[:309](../../src/epub2pdf/core/renderer.py#L309) CLI 回退用 `--no-margins`（注释“margins via @page CSS”）。两条路径都把边距完全交给 CSS。

### 2.4 Chromium 行为探针（决定方案）
用 `preferCSSPageSize: true` 调 `Page.printToPDF`，测文本 bbox：

| CSS `@page` | CDP margins 参数 | 结果 bbox（x0,y0,x1） |
| --- | --- | --- |
| `margin:18mm 16mm 20mm 16mm` | 0 | 51.0, 62.4, 541.1（CSS 生效） |
| `margin:0` | 0 | 6.0, 11.4, 589.5（贴边） |
| `margin:0` | 0.5in | 6.0, 11.4, 589.5（**参数被忽略**） |
| `margin:18mm…` | 0.5in | 51.0, 62.4, 541.1（参数被忽略） |

结论：**只要 `preferCSSPageSize: true`，CDP 的 margins 参数无效，CSS `@page` 是唯一决定因素**；因此原“方案 B”无效，必须走 CSS 清洗。
补充：CLI 回退路径实测尊重 CSS `@page`（同一 HTML bbox `x0=51.0, y0=62.6`），清洗后两条路径都会恢复边距。

## 6. 风险

- **过度删除**：清洗必须括号配平，只删 `@page` at-rule；`@media print { @page {…} }` 需递归处理，不能误删 `@media` 本体。缓解：单测逐形态覆盖。
- **EPUB 依赖 `@page` 做分页/尺寸**：本计划会删除其 `size`/margin box；我们的 `PRINT_CSS` 固定 A4，属预期行为；若某书依赖自定义纸张，需另开需求（非目标）。
- **内联 `<style>`**：正文内的 `<style>` 若含 `@page`，同样必须清洗；否则只修了外链样式表一半。
- **回归面**：现有 12 项 e2e、真实书 Mao/Spec 必须无变化；任何页数变动超过 ±2 页要停下排查。

## 8. 附：字号过小调研结论（独立问题，未列入本计划任务）

**事实**（`Spec-Driven AI Engineering`，用户旧产物 299 页；当前代码基线 303 页 / 626 条书签）：
- 代码只固定根字号：`html { font-size: 11pt }`（[normalizer.py:65](../../src/epub2pdf/core/normalizer.py#L65)），正文 `font-family/line-height/justify` 也在 `PRINT_CSS`；**没有任何“11pt 硬编码到每段”**。
- 该 EPUB 的 `OEBPS/stylesheet.css` 有 818KB、**2370 处 `font-size`**，正文类大量 em 值：`class_s1C-0` 无字号（继承 11pt）、`class_sH22/sH28` **0.71em（→7.81pt）**、`class_sH20` 0.76em（8.36pt）、`class_sGUW/sGUY` 0.86em（9.46pt）、`class_sH7` 0.95em（10.45pt）；嵌套时还会相乘（如 0.95×0.86≈0.817）。
- PDF 实测（全文 532,563 字符）：≥10.5pt 31.9%，9.5–10.5pt 29.4%，8.5–9.5pt 13.5%，**7.5–8.5pt 24.2%**，<7.5pt 0.9%；抽查页：p22 正文 11pt、图注/表 9.5pt；p33 清单表 8.9pt；p283 模板表 8.9pt/8.4pt。
- 结论：**字号主要由 EPUB 自身的 class CSS 决定（em 继承），代码只提供 11pt 根字号且不做下限/归一化**；该 EPUB 在普通阅读器里同样偏小（0.71em×16px≈8.5pt），我们的 11pt 根再缩小约 8%。

**可选修法（需决策，不在本计划）**：① 提高根字号（如 12pt，整体放大但标题同步变大）；② 对 `font-size` < 0.85em 的规则做下限重写（保留层级感）；③ 仅对表格/图注设最小 9pt；④ 不改代码，文档标注“部分 EPUB 字号由源文件决定”。三者的视觉回归成本不同，需用户选定后再立项（含 fixture 与 e2e 字号断言）。

3. **字号问题未混入**：§8 的字号策略需单独决策（改根字号会影响所有书），本版本不改。
