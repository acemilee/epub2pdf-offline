# v1.1 M3 书签来源对比实验报告（Chromium vs NCX）

- 日期：2026-10-20
- 计划版本：`docs/plans/v1.1.md` v0.2（M3）
- 代码基线：v1.1.0 开发中（未提交）
- 样本：`ebook/毛泽东选集 一至七卷 含静火版 (毛泽东) (z-library.sk, 1lib.sk, z-lib.sk).epub`
  - 2.8 MB，416 章（非封面章 415），5 张图片，EPUB 导航可解析出 410 条目标题

## 1. 实验方法

同一份 `index.html`（normalizer 输出）与同一份 `raw.pdf` 渲染路径，只改变 `outline_source`：

```powershell
# Chromium 大纲（默认）
F:\python313\python.exe -m epub2pdf --cli <book> -o output\v11_final_chromium.pdf
# NCX/EPUB 导航映射
F:\python313\python.exe -m epub2pdf --cli <book> -o output\v11_final_ncx.pdf --outline-source ncx
```

两份 PDF 的「生成目录页」都由同一批 `TocAnchor` 生成，因此目录页内容与页码完全一致，差异只在大纲（书签）结构。

## 3. 结论

1. **默认保留 Chromium 大纲**：同一本书多出 298 条大纲、多 2 层（h2/h3 小节级标题），导航体验明显更好。
2. **NCX 映射作为可选旁路保留**（`--outline-source ncx`）：适合"只想要章节级大纲"或 Chromium outline 缺失时；其层级完全取决于 EPUB 导航文档，本书只有 3 层。
3. 两者都不影响生成目录页与正文页码；目录页页码来自统一的锚点映射，与大纲来源无关。
4. 耗时差异不显著且主要是组装阶段的锚点文本抽取（见 §4），与大纲来源无直接关系。

## 4. 未解决项 / 后续

- 组装阶段（assemble）耗时约 250-270 s，占整本书 90% 以上；v1.0.1 同书为 ~56 s，疑似为 v1.1 新增的目录页/页码映射以外的因素（待 cProfile 结果确认；不阻塞 v1.1 发布，但需在 HANDOFF 中记录为 v1.2 性能项）。
- 9 条"页码不匹配"是校验脚本对脚注标记的误报，不是产物缺陷；后续 e2e 断言应使用"去脚注编号"后的标题比较。
