### 0.3 不能直接开工的原因（明确写死）

1. **Q1（目录页路线）未决**：A=不重制（只保留现有 nav 页，仅做页码叠加）、B=追加一张新目录页（保留 nav 页，会出现两份目录）、C=用新页替换 nav 页（影响原有阅读动线）。三条路线在 assemblies 中的合并顺序、页码偏移、书签数量都不同。
2. **Q2（书签默认源）未决**：Chromium outline 实测 708 条/5 层/412 章覆盖；NCX 的理论覆盖更高（含 Part 层与 Dedication 等），但**未做真实书实验**，不能先写死。
3. **Q3（TOC 条目来源）未决**：TOC 页码必须与最终书签同源，否则会出现"目录页码对、书签页码错"。
4. **T4.3 的自增算法未做原型**：两遍渲染是否稳定（标题换行导致页数抖动）尚未验证。
5. 候选 5 已由实测证伪"内存瓶颈"假设（峰值 280.2MB / 68.5s，见 §5.1），结论是**不施工**，而不是"按原计划优化"。

## 1. 目标与非目标

### 1.1 目标（v1.1.0）

1. **阅读体验**：把"看起来像原生 PDF"再推进一步——目录页带真实页码与引导线（避免当前 nav 页只有链接、无页码），书签覆盖更完整、层级与目录一致。
2. **可靠交付**：封面支持 SVG/AVIF/BMP（当前静默空白），TIFF 有明确告警策略。
3. **可用性**：GUI 增加"打开输出目录"按钮（全局路径，存在性感知）。
4. **工程可信**：新增能力全部有 e2e 断言；打包产物与源码一致。

### 1.2 非目标

- 候选 4（预览下划线）：无预览组件，先立新功能（Q7）。
- 候选 5（大书内存）：实测无瓶颈（峰值 280MB），不立项；仅保留观测门槛（>1GB 再立项）。
- 固定版式 EPUB、DRM 破解（沿用 v1.0 结论）。
- 多语言字体策略重构（现有并集嵌入足够）。

### M3 NCX 书签映射（1.5 人日，Q2 决定是否默认）

### 11.2 执行中发现并修复的新问题
